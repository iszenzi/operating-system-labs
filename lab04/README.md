# Лабораторная работа 4

Вариант 7. Процессы и обмен данными через отображаемый файл.

## Задание

Повторяется вариант 7 из ЛР №2: пользователь вводит имя файла,
дочерняя программа читает его через стандартный ввод и суммирует числа
типа `float` в каждой строке. Родитель выводит полученные суммы в консоль.
В ЛР №4 вместо канала используется отображаемый файл (`mmap`).

```text
файл -> stdin child -> сумма строки -> mmap файла результатов
     -> waitpid в parent -> mmap для чтения -> stdout parent
```

## Сборка и запуск

Среда — Linux, в том числе Ubuntu в WSL 2. Нужны GCC и Make.
Для демонстрации системных вызовов дополнительно нужен `strace`.

Из корня репозитория:

```sh
make -C lab04
cd lab04
./build/parent
```

Введите путь `examples/numbers.txt`. Результат:

```text
3
8
75.125
0
-4
42.5
0.875
0
55
1.00100005
```

Можно выполнить `make -C lab04 run` из корня репозитория.
Рабочая папка программы должна быть `lab04`: дочерняя программа
запускается по пути `./build/child`. Входной путь задаётся относительно
`lab04` либо как абсолютный путь. Диагностика и PID идут в `stderr`,
числовые результаты — в `stdout`.

## Как устроен обмен

1. Родитель открывает входной файл и создаёт временный файл через `mkstemp`.
   Имя временного файла сразу удаляется через `unlink`. Открытый дескриптор
   продолжает работать; после закрытия всех дескрипторов и отображений
   временный файл освобождается ОС.
2. После `fork` дочерний процесс связывает входной файл со `stdin`,
   временный файл — со `stdout` через `dup2`, затем запускает `build/child`
   через `execl`. Это отдельная исполняемая программа, как в ЛР №2.
3. Дочерняя программа читает строки через `getline` и считает суммы.
   Для каждой суммы `ftruncate` увеличивает файл результатов,
   `mmap` с `MAP_SHARED` отображает его в память, `memcpy` дописывает
   строку результата, `munmap` снимает отображение. Для обращения
   к файлу результатов используется дескриптор стандартного вывода.
4. Родитель дожидается ребёнка через `waitpid`, узнаёт итоговый размер
   через `fstat`, отображает файл для чтения и выводит его содержимое.
   Результаты появляются после завершения дочерней программы.

Одновременного чтения и записи нет: ожидание через `waitpid` разделяет
эти этапы. Дополнительные сигналы, семафоры и `msync` не нужны:
`MAP_SHARED` делает изменения видимыми через отображения того же файла;
сохранять временный файл на физический носитель не требуется.
Для простоты файл отображается заново при добавлении каждой суммы.

## Входные данные и ошибки

Разбор чисел перенесён из ЛР №2. Количество чисел в строке не ограничено
фиксированным буфером: `getline` увеличивает его при необходимости.
Поддерживаются отрицательные числа, пробелы, табуляция и экспоненциальная
запись. Десятичный разделитель — точка. Пустые строки пропускаются;
пустой файл завершается без результатов. Последняя строка может быть без
перевода строки.

Неверное число, `NaN`, бесконечность, выход за диапазон или переполнение
суммы приводят к сообщению об ошибке и ненулевому коду завершения.
Суммы предыдущих корректных строк сохраняются. Сумма вычисляется в `float`
и выводится с `FLT_DECIMAL_DIG` значащими цифрами, поэтому возможна обычная
погрешность округления.

Проверяются ошибки создания процесса, открытия и изменения размера файла,
отображения памяти, записи и ожидания. Отображения снимаются, дескрипторы
закрываются, память строк освобождается. Родитель ожидает дочерний процесс
и при ошибках. Игнорирование `SIGPIPE` позволяет обработать ошибку вывода,
если потребитель стандартного вывода закрыл канал.

## Демонстрация системных вызовов

Из корня репозитория:

```sh
make -C lab04 trace
```

В `lab04/artifacts/` сохраняются `results.txt`, `processes.log` с PID
и `trace.log`. В трассе нужно найти создание и удаление имени временного
файла (`openat`, `unlink`), создание процесса (`clone`), перенаправление
(`dup2`), запуск `build/child` (`execve`), изменение размера (`ftruncate`),
отображение и снятие отображения (`mmap`, `munmap`), ожидание (`wait4`).
В Linux библиотечные `fork` и `waitpid` могут отображаться как `clone`
и `wait4`. Вызов `memcpy` работает с памятью и в `strace` не отображается.

Каталоги `build/` и `artifacts/` исключены из Git. Команда `make clean`
из `lab04` удаляет только результаты сборки.
