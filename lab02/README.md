# Лабораторная работа 2

Вариант 7. Управление процессами и обмен данными через неименованный канал.

## Задание

Пользователь вводит имя файла в консоль родительской программы.
Родитель открывает файл и создаёт дочерний процесс. В дочернем процессе
стандартный ввод перенаправляется на файл, стандартный вывод — в канал.
Затем дочерний процесс запускает отдельную программу, которая суммирует
числа типа `float` в каждой строке. Родитель читает результаты из канала
и выводит их в свою консоль.

```text
файл -> stdin дочерней программы -> сумма -> stdout -> pipe -> родитель -> stdout
```

```text
lab02/

├── include/

│   ├── child.c
│   ├── io.c
│   └── sum.c
├── tests/
│   └── test_lab02.cpp
├── build/

```

`build/` содержит исполняемые программы, объектные файлы и исполняемый
файл тестов. `artifacts/` содержит результаты запуска и логи трассировки.
Эти папки создаются автоматически и исключены из Git.

## Сборка и запуск

Программы собираются GCC как C17. Для обычной сборки нужны только GCC и Make.
Для тестов дополнительно нужны G++, Google Test и команда `timeout`
из пакета `coreutils`. Тесты собираются как C++17; Google Test не используется
в самих программах. Для трассировки нужен `strace`.

Установка зависимостей в Ubuntu:

```sh
sudo apt update
sudo apt install build-essential libgtest-dev coreutils strace
```

Перейдите из корня репозитория в папку лабораторной:

```sh
cd lab02
make
./build/parent
```

На приглашение «Введите путь к файлу» укажите:

```text
examples/numbers.txt
```

Результат в стандартном выводе:

```text
3
8
75.125
0
-4
42.5
0.875
0
55
1.00100005
```

Запуск с заранее заданным именем файла из папки лабораторной:

```sh
printf '%s\n' examples/numbers.txt | ./build/parent
```

Из корня репозитория можно запустить программу через Make:

```sh
make -C lab02 run
```

При таком запуске имя входного файла также задаётся относительно папки
`lab02`, например `examples/numbers.txt`. Допускается абсолютный путь.

Родитель запускает дочернюю программу по пути `./build/child`, поэтому
рабочей папкой при запуске должна быть `lab02`.

Подсказки и сообщения программы написаны на русском языке. Системное
пояснение, добавляемое `perror`, зависит от локали ОС.
Сообщения с PID и ошибки направляются в `stderr`, числовые результаты —
в `stdout`. Оба процесса возвращают ненулевой код при ошибке.

## Входные данные

- В строке может находиться произвольное число чисел; буфер растёт через `getline`.
- Числа разделяются пробельными символами. Десятичный разделитель — точка.
- Поддерживается экспоненциальная запись, например `1.25e2`.
- Пустые строки пропускаются. Пустой файл завершается успешно без результатов.
- Последняя строка может не заканчиваться переводом строки.
- Неверный токен, `NaN`, бесконечность, ошибка диапазона `strtof` или
  переполнение суммы завершают обработку с ошибкой. Результаты ранее
  обработанных строк сохраняются в выводе.
- Сумма накапливается в `float`; вывод содержит до `FLT_DECIMAL_DIG`
  значащих цифр. Возможны обычные погрешности арифметики с плавающей точкой.

## Исходные файлы

| Файл | Назначение |
| --- | --- |
| `src/parent.c` | Создание процесса, настройка потоков, чтение канала и ожидание |
| `src/child.c` | Чтение строк, вывод результатов и диагностика |
| `src/sum.c`, `include/sum.h` | Разбор чисел и вычисление суммы строки |
| `src/io.c`, `include/io.h` | Полная запись, обработка SIGPIPE и закрытие дескрипторов |
| `tests/test_lab02.cpp` | 9 тестов Google Test: 7 проверок суммы и 2 проверки запуска |
| `examples/numbers.txt` | 10 строк корректных входных данных |
| `Makefile` | Сборка, запуск, тесты, трассировка и очистка |

Сборочные файлы находятся в `build/` и не добавляются в Git.
Очистка из папки лабораторной: `make clean`. Эта команда удаляет `build/`;
сохранённые логи в `artifacts/` остаются.

## Проверки

Из корня репозитория:

```sh
make -C lab02 test
make -C lab02 trace
```

Первая команда запускает 9 тестов Google Test. Вторая сохраняет
результаты, сообщения с PID и трассу системных вызовов в `lab02/artifacts/`.
Повторная трассировка перезаписывает эти логи:

| Файл в `artifacts/` | Содержимое |
| --- | --- |
| `results.txt` | 10 числовых результатов для файла примера |
| `processes.log` | Сообщения с PID и ошибки программы |
| `trace.log` | Системные вызовы родителя и дочернего процесса |
